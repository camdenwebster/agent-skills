# Swift starting set — qualitative decision, 2026-11-24

Stop expanding or running skill-comparison campaigns for now. Select guidance by project fit, clear scope, complementary coverage and manageable dependencies. The evaluation framework remains available on demand; comparative scores are not a prerequisite for beginning native adaptation.

This is a qualitative selection, not a measured winner claim. It uses the 19 exact snapshots in [the shortlist](../evals/swift-benchmarks/shortlist.md), inspected entrypoints, and the earlier [source research](swift-research.md). Public repository pages were refreshed on Nov 24, but candidate revisions were not upgraded. Historical compatibility snapshots are not the latest release. Existing evals, pins and raw results are unchanged.

## Chosen starting set

| Work | Primary guidance | Why |

| Unit/integration testing | Antoine van der Lee — Swift Testing | Framework boundaries, dependency isolation, modern assertions and parallel safety |

| Performance work | Thomas Ricouard — SwiftUI Performance Audit | Symptom-driven investigation with explicit profiling evidence |
| Architecture/design | Matt Pocock — Codebase Design | Deep modules, small interfaces, explicit dependencies and testable behavior |

These six are the starting collection, loaded by task rather than all injected into every session. Keep the catalog's existing review/TDD workflows as the process foundation. Add selected Axiom Data and Run Tests references on demand for persistence and native evidence. Apple SDK/compiler documentation and the consuming project's rules remain authoritative. For MovingBox specifically, SQLiteData/SyncEngine registration and additive schema rules override generic migration advice.

The six primary selections are now installed project-locally under `.agents/skills/`, with exact source pins, supporting resources and MIT notices. [The active routing contract](../docs/native-skill-routing.md) connects them to this checkout's Lead/Architect/Coder/Reviewer/QA workflow through AGENTS.md and CLAUDE.md. Claude discovery links share the canonical copies. Global/shared role installations and the distributable root plugin catalog are unchanged; optional alternatives below remain references, not new installs.

## Other researched sources

- **Apple/Xcode:** first-party grounding for SDK behavior, SwiftUI identity/dataflow, localization and App Intents. Discover installed capabilities per toolchain. Keep bundled skill text external rather than assuming permission to relicense it in this public fork.
- **Emil's mobile/design pack:** useful interaction and motion reference. It includes native Swift guidance as well as web/Expo material; do not adopt the whole pack as a native implementation default. Use design intent selectively, with native accessibility and Reduce Motion checks.
- **Antoine's build optimization skill:** useful later for an observed build-time problem; it adds no necessary daily role now.
- **SwiftFairy:** deferred optional paid specialist. No purchase/trial or dependency is needed for this starting set.
- **Point-Free skills:** optional licensed project expertise for existing library use. Keep private skill text out of the public fork and evaluation corpus; use independently licensed public library docs for redistributable grounding.

## When to revisit with evals

Run a small targeted comparison only when a real decision warrants it: a repeat failure, conflicting advice, a consequential candidate upgrade, or a specialist whose benefit is uncertain. Start from the actual failure, add a clean control, set a call budget, and preserve the old suite version. Follow the [on-demand runbook](../evals/swift-benchmarks/on-demand.md).

The earlier small testing cases did not demonstrate a skill advantage; the later multi-file no-skill baseline received LLM 5/5 but only three assertion kills plus one incomplete mutation. That shows why we retain native functional checking, not that any candidate would perform better. Do not require more benchmarking before adopting the practical starting set above.
